---
name: law-of-demeter
description: Check Java code for Law of Demeter violations and hybrid classes with the law-of-demeter CLI, then fix what it reports. Use after writing or changing Java code, or when asked to check a Java project for Law of Demeter.
---

**Run the check after every Java change and treat findings like failing tests.**

- Read `law-of-demeter --help`. If the CLI is missing, install it from the tool's repository root with `cargo install --path crates/cli`. `law-of-demeter update --pull` refreshes the CLI and this skill.

- The tool reads source together with compiled classes, so a method generated by Lombok or a library type is known only after a build.

## Run the check

---

**Build first, then run the tool in the project root.**

- **Maven project:**

  - Build and write the dependency list: `mvn -q compile dependency:build-classpath -Dmdep.outputFile=target/classpath.txt`

  - Run `law-of-demeter` without arguments. It finds every `src/main/java`, `target/classes` and `target/classpath.txt` itself, including submodules.

- **Other layouts:** Pass every source root with `--source` and the compiled classes and jars with `--classpath`. Types missing from the source roots count as library types, so give all modules.

- **Focused check:** Use `--only shop.Order` for a class or `--only shop.Order#pay` for a method. Do not narrow `--source` for this: violations through types outside the source would be missed.

- **Why a call is allowed:** Add `--show-allowed` to list allowed calls with the rule they follow.

## Read the result

---

**The exit code is the verdict; the report on standard output gives the details.**

- **Exit code 0:** No violations and no hybrid classes.

- **Exit code 1:** Violations or hybrid classes found. Fix them before finishing.

- **Exit code 2:** The check did not run: usage error, no source root, no JDK, or `--only` matched nothing. Read the `Error:` line on standard error.

- **Violation line:** `file:line  class.method  call()  Violation: reason`. The reason names where the stranger came from, such as `the object returned by getCustomer() is not a friend of f`.

- **Hybrid class line:** Lists the class's behavior methods and the getters or setters that expose its data.

- **Unresolved calls, source errors and type reading errors** do not change the exit code. Rebuild and pass the missing classpath when they appear; the check is incomplete until they are gone.

## Fix a finding

---

**Move the work to the object that owns the data; do not hide the chain.**

- **Chain through a stranger:** Replace `order.getCustomer().getWallet().withdraw(amount)` with a method on the friend, such as `order.charge(amount)`, and let `Order` reach its customer.

- **Streams, lambdas and method references:** They do not hide a stranger. `orders.forEach(order -> order.charge(amount))` is the fix for `orders.stream().map(Order::getCustomer).forEach(...)`.

- **Data structure:** A chain through types that only carry data is allowed. Turn a type into a `record` only when it really has no behavior.

- **Hybrid class:** Remove the getters and setters that let callers bypass the behavior, and call the behavior instead, such as `account.withdraw(amount)` instead of `account.setBalance(account.getBalance() - amount)`.

- **Do not cheat the check:** Storing the stranger in a local variable, a loop variable or a non-`private` helper does not make it a friend; the tool tracks it.

- Run the check again after each fix.

## False alarms

---

**Report a finding you believe is wrong instead of rewriting correct code.**

- Confirm with `--show-allowed` and `--only` on the method, then tell the user which line and reason look wrong.
